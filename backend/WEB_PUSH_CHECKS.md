# Результаты проверки — 17 ноября 2026

Окружение: macOS, Python 3.14, PostgreSQL 17 в отдельном Docker-контейнере.
Общий FastAPI backend успешно запущен на тестовой базе; VAPID-ключи созданы
в памяти только на время проверки.

## Выполнено

- 4 автоматических теста прошли: отправка, пустой список, обработка 410,
  жизненный цикл подписки на настоящем PostgreSQL.
- PostgreSQL: повторный endpoint обновляет ключи без дубля, запись остаётся
  после закрытия и пересоздания пула соединений; отписка исключает endpoint
  из активных получателей; повторная подписка активирует его.
- Общий сервер отдаёт `/web-push/` и `/web-push/sw.js` с HTTP 200.
- В Google Chrome тестовая страница открылась, Service Worker активировался,
  кнопка подписки вызвала браузерный запрос разрешения.

## Повторная браузерная проверка

Google Chrome 157.0.0.0, macOS. Повторный запуск инструмента позволил разрешить
уведомления и получить настоящую PushSubscription. В PostgreSQL появилась одна
активная подписка. Ручной POST `/api/push/send-test` вернул
`total: 1, sent: 1, removed: 0, errors: []`.

Старые уведомления закрыты через `getNotifications()`. Вкладка тестовой страницы
закрыта; Python повторно отправил push. После открытия страницы
`ServiceWorkerRegistration.getNotifications()` вернул новое уведомление
с заголовком «Питомец рядом» и текстом «Тестовое Web Push уведомление».
Таким образом, подтверждён показ уведомления Service Worker при закрытой вкладке.
Видимость системного баннера отдельно не подтверждалась.

Процесс FastAPI остановлен и запущен заново: до повторного открытия страницы
PostgreSQL по-прежнему содержал одну активную подписку. После браузерной кнопки
«Отписаться» общий модуль отправки вернул
`total: 0, sent: 0, removed: 0, errors: []`: получателей для дальнейшей доставки нет.

Клик по системному уведомлению и видео получения push не зафиксированы.
Временные VAPID-ключи существовали только в памяти первого тестового процесса;
повторная отправка после перезапуска не выполнялась. Для обычного запуска
нужно сохранять одну и ту же пару ключей в секретах окружения.

Основной `frontend/` в PR не изменён. `/web-push/` — отдельная проверочная
страница согласно заданию, не замена основному интерфейсу сайта.

## Запуск автоматических проверок

Из папки `backend`, в активированном окружении:

```bash
python -m unittest discover -s tests -v
```

Для интеграционного теста задайте `PUSH_TEST_DATABASE_URL`, указывающий на
отдельную тестовую PostgreSQL. Без него тест PostgreSQL пропускается.
