## Данные

Использовать только свои записи с `[QA ТЕСТ]` в кличке. Сохранять ID, после проверки удалять и перечитывать список и запись по ID. Чужие записи не менять.

В [qa-test-data.csv](qa-test-data.csv): QA-001–010 — корректные данные, QA-011–015 — ошибки, QA-016–020 — модерация. Ожидания в CSV не являются результатами выполненных тестов.

Сопоставление с текущим API:

| CSV | JSON |
|---|---|
| Кошка / Собака | species: cat / dog |
| Потерян / Найден | report_type: lost / found |
| Описание | comment |
| Место | street |
| Контакт email | contact_email |
| Номер | name: `[QA ТЕСТ] QA-001` и т. д. |

Тип объявления не равен статусу поиска `active/found`. По OpenAPI сервера обязательны species (2–50 символов), street (2–100), comment (1–340), contact_email (5–100). name необязательно, максимум 100; report_type — lost/found, по умолчанию lost. Формат email и trim в схеме не заданы.

Для UI отдельно использовать вымышленный телефон `+12025550142` или строку Telegram `@qa_example_001` (принадлежность аккаунта не проверялась). Сообщения и звонки не отправлять. Эти значения нельзя подставлять в contact_email: контракт телефона/Telegram ещё не согласован.

QA-011: удалить species из JSON, не передавать пустую строку вместо отсутствующего ключа. QA-012: comment из трёх пробелов. QA-014: species как настоящий объект `{"value":"cat"}`. QA-015: street из 101 символа. Маркер теста сохранять в name.
